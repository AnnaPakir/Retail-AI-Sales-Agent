# Как я разбираю процесс в первые 90 минут

Это практический шаблон для новой автоматизации, а не обещание сразу написать бота.

## 0–20 минут: границы процесса

- кто начинает процесс и каким событием;
- где он заканчивается;
- какие системы и люди участвуют;
- что считается полезным результатом;
- какие решения нельзя отдавать ИИ.

Результат: короткая схема happy path и список запрещённых действий.

## 20–45 минут: реальные примеры

Беру 10–20 обезличенных кейсов: обычные, редкие и неудачные. Для каждого отмечаю вход, ожидаемый ответ, нужные данные, владельца данных и условие handoff.

Результат: первая таблица сценариев, а не абстрактный «умный помощник».

## 45–65 минут: данные и интеграции

Проверяю, откуда берутся факты, насколько они свежие, можно ли получить их через API и кто исправляет расхождения. Отдельно фиксирую PII, секреты, повторы webhook и ограничения каналов.

Результат: source-of-truth map и список технических рисков.

## 65–80 минут: минимальный контур

Выбираю один полезный сценарий и один безопасный fallback. Решаю, где достаточно правила, где нужен поиск, где LLM, а где человек.

Результат: MVP, который можно проверить на конкретных примерах.

## 80–90 минут: критерии приёмки

Определяю 5–10 первых evals, обязательные traces и метрики: доля корректной маршрутизации, tool-call accuracy, groundedness, handoff rate, latency и стоимость.

Результат: понятный план следующего шага и список вопросов владельцам процесса.
