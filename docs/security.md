# Модель угроз публичного демо

## Что защищаем

- корректность цены и наличия;
- системные правила и внутреннюю структуру данных;
- персональные данные клиента в журналах;
- CRM от повторной обработки одного события;
- человека от автоматического решения, на которое у агента нет полномочий.

## Реализованные ограничения

- инструменты принимают только `product_id` и возвращают минимальный набор полей;
- произвольный SQL отсутствует;
- секреты читаются только из окружения и не нужны для demo mode;
- `request_id` обеспечивает идемпотентность в рамках процесса;
- телефон, e-mail и номер заказа маскируются до записи trace;
- LLM получает только выбранный контекст, а не весь каталог или историю БД;
- новые числа в LLM-ответе вызывают fallback на исходный контекст;
- операции с заказом, ремонтом, скидкой и оптом запрещены автоматическому контуру.

## Что ещё нужно для production

- внешний secret manager и ротация ключей;
- авторизация на API и подпись webhook;
- PostgreSQL/Redis idempotency с TTL;
- шифрование журналов, retention policy и role-based access;
- защита retrieval от poisoned documents;
- rate limiting и лимиты размера вложений;
- red-team набор для prompt injection, data exfiltration и tool abuse;
- allowlist доменов для исходящих интеграций;
- аудит действий оператора после handoff.

Числовой guard — только дополнительная проверка. Он не доказывает смысловую верность текста и не заменяет grounded evals.
